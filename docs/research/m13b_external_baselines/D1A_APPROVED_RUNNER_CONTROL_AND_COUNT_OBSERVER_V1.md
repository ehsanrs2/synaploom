## Work implemented

1. **Offline control plane** (src/synaploom/research/m13b_d1a_runner_control_cpu.py). Build a full 720-slot synthetic registry in alternating arm order (180 pairs each direction). Draw index, not seed value, defines the pair identity; the toy registry intentionally repeats values 13 and 17 to test duplicates without selecting any scientific seeds. Replay exactly the closed ordered prefix; reject out-of-order, duplicate, retry, overlapping and malformed records; fail closed after failure, timeout or timing overrun. Account elapsed occupied time from a common zero origin, including idle gaps, and require sufficient budget for full per-attempt worker timeout plus synthetic cleanup allowance before a start. Every not-started slot is enumerated. An incomplete or invalid registry is not eligible for statistical analysis. The expected detached digest must match the complete replay envelope. This is offline validation of supplied timestamps, not an actual monotonic-clock watchdog, immutable journal or proof that an attempt really happened; the caller-supplied digest is not cryptographically authenticated.
2. **Actual evaluator observation**. TaskEvaluation now retains the exact integer correct count produced by the existing evaluate_task loop. The new optional evaluation_count_observer in run_continual_experiment emits only fresh primitive dictionaries with phase, stage, task ID/index, epoch, global step, batch size, correct and example count. It runs before float32 stage matrix assignment. It rejects missing/inconsistent counts when enabled. No default accuracy/loss calculation, batch composition, result JSON schema or training policy is changed. TaskEvaluation has an additional optional dataclass field (excluded from equality and repr); callers introspecting its fields/asdict can see it. The sink is trusted code, not an isolation or secrecy boundary. Real science must use a sealed sink inaccessible to preclosure design/monitoring.
3. **Full event adapter**. The synthetic count contract requires all 200 epoch evaluations and all 55 lower-triangle stage evaluations in actual runner order, 1,000 examples each, B256, exact task/index/epoch and step sequence (40 steps per epoch), integer counts only. The full-shape adapter checks event geometry, not the identity of actual examples or actual optimizer post-hooks. Recompute both co-primary fractions directly from correct counts: final row / 10,000 and final two tasks' 40 epoch counts / 40,000. Do not recover counts by rounding old floating summaries.
4. **Exact fixed-stake decision**. Only after the complete fixture is closed and each observation digest/slot identity matches the replay, pair by draw index, compute the exact rational product of (1+D) for each metric and compare against 20 without float threshold rounding. For reporting, invert E(m)=E(0)/(1+m)^360 on a millionth-unit grid using exact rational comparisons; report a downward-rounded marginal one-sided 95% lower bound (−1 for zero wealth). Equality at threshold rejects; the lower bound may be rounded to zero; both component rejections required. This is a synthetic analysis interface, not an accepted scientific inference engine until independent implementation review and assumption checks. No interim decision API in this replay module; the actual worker/result access control remains to implement.
